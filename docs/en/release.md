# Release dossier: 1.1.0-rc.1

**Governed AI Workflow Platform**
**Ahad Porkar | 12 October 2026**

> AI may investigate uncertainty. It does not inherit the authority to act.

## Release story

This release candidate adds a governed exception-handling reference to the order-to-cash portfolio: case-scoped read tools, bounded planning, deterministic policy, independent review, durable execution receipts and a visible recovery path. A polished English/German console makes the control boundaries inspectable rather than hiding them behind a successful chat transcript.

The most important demonstration is deliberately unglamorous: terminate the worker at the acknowledgement gap and show that the synthetic refund is not repeated. That is the difference between a plausible assistant response and an accountable business operation.

## Included artifacts

The source package contains the Java core and offline build, local server/worker, EN/DE UI, automated tests, labelled evaluation, OpenAPI, an additive Spring/Camunda/PostgreSQL/Kafka overlay, BPMN, SQL migration, installation safeguards, source provenance, bilingual technical guides, release PDFs and LinkedIn publication drafts.

The added-file manifest records source paths, target paths, hashes and operation types. No existing files are modified or deleted. The uploaded RechnungFlow archive remains untouched. The requested host repository was inspected publicly but not cloned or merged here.

## Evidence worth showing

106 Java contract tests and 29 actual HTTP/process tests passed in the recorded run. Nine browser checks passed using an explicitly disclosed DOM harness because native navigation was blocked. Additional repository checks and final totals are in the verification report. Thirty-two concurrent direct retries and twelve concurrent HTTP retries are separately exercised.

The independent recovery experiment includes a genuine worker-process crash, server restart and one committed receipt. The baseline evaluation reports 33 exact proposals and 40 acceptable dispositions across 48 cases; it does not claim model excellence.

## Exit criteria before a final integrated release

- [ ] Apply the overlay to a recorded clean host commit and review all changes.
- [ ] Pass the host Maven build and PostgreSQL concurrency/rollback tests.
- [ ] Deploy BPMN and prove Kafka/Camunda automatic progression and failure recovery.
- [ ] Run native-browser tests, keyboard/accessibility review and Windows checks where supported.
- [ ] Evaluate an actual model on a separately held-out dataset and publish failures/cost assumptions.
- [ ] Decide whether the release remains a sandbox; implement and reconcile real connectors before claiming real business effects.
- [ ] Replace demo identity and review the security of all host APIs before public exposure.
- [ ] Review licenses, privacy/retention, deployment hardening, backups and load characteristics.

Only rename the candidate to a final integrated release after the relevant gates have recorded evidence. A portfolio sandbox can be published honestly as a candidate without implying production certification.
