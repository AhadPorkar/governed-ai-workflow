# Publication checklist

These are ready-to-edit release-candidate materials, not posts already published to an account.

1. Apply/review the overlay or publish the independent reference package as an explicitly scoped release candidate. Record the real repository commit.
2. Make the referenced release assets and documentation accessible before posting. Replace the general repository link with the actual release permalink when available.
3. Keep the sandbox and release-candidate labels. Do not claim native browser, Camunda stack, real-model or production acceptance before recording it.
4. Use one language per LinkedIn post. The English and German PDF document decks have matching content and editable PowerPoint sources.
5. Show only synthetic data. Never include `.local/access.json`, real requests, employer code or credentials.
6. Review all text in your own voice. The drafts describe this delivered implementation, not invented employment accomplishments.

The release dossier is a technical overview; the LinkedIn document is a visual narrative. Long-form articles, short posts, project summaries and CV bullets are supplied separately. No external publication, GitHub write, LinkedIn update or deployment has been performed.
